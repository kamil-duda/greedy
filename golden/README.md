# Golden corpus

What the 2017 implementation produces, recorded once, so every later implementation can be checked against it. The corpus is plain files: it does not depend on Java, Scala or the legacy build, and it stays after `legacy/` is deleted. Background: `PLAN.md` (Testing strategy, Behavior-change registry) and `docs/plans/phase-0.md` (Tasks 8–10).

## Layout

| Path | Contents |
|---|---|
| `inputs/fixtures/` | Copies of the legacy test fixtures (`src/test/resources/files`): `paper-sample`, `complex-sample`, `sample`, `inconsistencies`, `tic-tac-toe` |
| `inputs/public/` | Public categorical datasets from the UCI Machine Learning Repository (attribution below) |
| `inputs/random/` | 100 seeded random small decision tables (`random-001` … `random-100`) |
| `inputs/edge/` | Hand-made edge cases (table below) |
| `outputs/` | Legacy outputs, the manifest and the nondeterminism report (generated by `make legacy-golden`) |
| `scripts/` | The scripts that produced `inputs/public` and `inputs/random` |

An input's **id** is its path under `inputs/` without `.csv`, e.g. `public/lenses`. Every input has a header row with the decision attribute last; all values are read as strings.

## How the inputs were made

```bash
# public: unpack the four UCI archives (URLs below) into an empty directory, then
python3 -I golden/scripts/prepare_public_datasets.py --source-dir <dir> --out golden/inputs/public
# random
python3 -I golden/scripts/generate_random_tables.py --seed 20261027 --count 100 --out golden/inputs/random
# fixtures
cp src/test/resources/files/{paper-sample,complex-sample,sample,inconsistencies,tic-tac-toe}.csv golden/inputs/fixtures/
```

Public datasets keep their values unchanged; only id columns are dropped (lenses: row number; zoo: `animal_name`; monks: `data_N`), a header is added and, for monks, the class moves to the last column. Random table *i* is drawn from `random.Random(20261027 + i)` (Python 3.15.2): 3–40 rows, 1–5 condition columns `c1…cK` with 2–4 values from `0 1 2 3`, decision `d` with 2–3 values from `a b c`, and with probability 0.1 one empty cell. The committed files are the reference; a different Python version may draw differently.

### Edge inputs

| File | Content | What it pins |
|---|---|---|
| `empty-file` | 0 bytes | no header at all |
| `header-only` | `a,b,d` | no rows |
| `single-row` | `a,d` / `1,y` | degenerate table |
| `single-decision` | `a,b,d` / `1,2,y` / `2,3,y` | at most one decision value: no rules |
| `single-condition` | `a,d` / `1,y` / `2,n` / `1,n` | one condition column with an inconsistent pair |
| `identical-rows` | `a,b,d` / `1,1,y` ×3 | duplicates only |
| `mcd-tie` | `a,d` / `0,y` / `0,n` / `1,y` / `2,n` | most-common-decision tie (registry #2) |
| `empty-cells` | `a,b,d` / `,1,y` / `,1,n` / `2,2,n` | empty cells in an inconsistent group (registry #10) |
| `quoted-values` | `a,b,d` / `"x,1",p q,y` / `"say ""hi""",p q,n` / `z,r,n` | quotes, commas and spaces inside values |
| `dotted-names` | `a.b,c,d` / `1,1,y` / `2,1,n` | dot in a column name (registry #11) |
| `duplicate-names` | `a,a,d` / `1,2,y` / `2,1,n` | repeated column name (registry #11) |
| `bom-crlf` | UTF-8 BOM, `a,d` / `1,y` / `2,n` with CRLF line ends | Excel-style export |
| `unicode` | `wiek,łzawienie,decyzja` / `młody,tak,ą` / `stary,nie,ę` | non-ASCII names and values |
| `numeric-like` | `a,d` / `01,y` / `1,n` / `1.0,y` | values are strings, not numbers |
| `whitespace` | `a,d` / ` x ,y` / `x,n` | leading and trailing spaces are kept |

## Outputs and comparison

`make legacy-golden` runs the legacy pipeline (CSV read → decision tables → most-common-decision → heuristic → formatter) for every input × 5 heuristics × 2 modes × 3 formats, twice with different Spark parallelism, and writes:

- `outputs/<input id>/<mode>-<heuristic><suffix>`: `dt` or `is`; `m`, `rm`, `maxCov`, `poly`, `log`; `.csv`, `.rul` or `-wmetadata.csv`.
- `outputs/manifest.json`: every case with its outputs, or the exception class when the legacy code failed.
- `outputs/nondeterministic.json`: cases whose output differed between the two runs.

Outputs are compared order-insensitively, because legacy output order is arbitrary: `.rul` as a sorted list of lines; `.csv` with the leading index taken off each line, sorted, plus the set of indices, which must run 0..n−1 across all rules (legacy numbering does, in every golden file); `-wmetadata.csv` the same for rule lines, with the header and the six statistics lines compared verbatim. The reference implementation is `GoldenFiles.normalize` (`src/test/java/org/kduda/greedy/golden/GoldenFiles.java`).

Every nondeterministic case comes from a most-common-decision tie (registry #2). The list is a lower bound: 110 input-modes contain such a tie, and only 42 resolved differently in these two runs. Treat a mismatch on any tie-dependent case as a possible tie, not a regression.

Partial runs, e.g. to check one input: `make legacy-test-one T=GoldenGenerator ARGS="-o '-Dgolden.include=^public/lenses$' -Dgolden.out=target/golden-check"` (the regex is matched against input ids; quote it inside `ARGS`).
